## Architecture and baseline

The site has 50 recipe documents, static recipe detail pages, an on-demand listing, interactive React islands, Auth.js, Neon/Drizzle, and ImageKit. Astro's static HTML is a good fit for editorial content. Functions and content modules are preferable to classes where there is no mutable domain object or second adapter. OOP/SOLID here means a small, cohesive interface for recipe querying and API validation, explicit dependencies, and no unnecessary inheritance. The existing `RecipeCard` and `RecipesList` modules are useful seams; indiscriminate classes would add surface area without behavior.

At the start of the audit, the working tree was clean and dependencies were absent. `npm run build` and `npm test` could not run (`astro` and `vitest` not found). The global ESLint command could not resolve project packages. Validation results after installation are recorded below.

## Audit results

### Critical issues (3 found)

- **[Trust / privacy]** `src/pages/api/contact.ts:5` logs a submitted message and returns success without delivering it. The page tells users the team will reply. **Impact:** sensitive content is logged and messages are silently lost. **Fix:** provide an honest contact path until a delivery provider is configured; remove the fake endpoint.
- **[Trust]** `src/pages/api/subscribe.ts:5` logs email addresses and returns success without storing subscriptions; `src/components/react/forms/SubscribeForm.tsx:28` treats any HTTP response as success. **Impact:** false subscription and email exposure in logs. **Fix:** remove the misleading signup flow until real storage and consent exist.
- **[Security]** `src/pages/api/image-kit/auth.ts:1` did not opt out of prerendering, and the route was absent from private-route protection. **Impact:** an upload signature could be issued to anonymous visitors or embedded in static output. **Fix:** render on demand and require the authenticated middleware path.

### High priority (8 found)

- **[Performance / LCP]** `src/components/astro/pages-structure/BaseHead.astro:43` preloads 15 TTF fonts on every page. `public/fonts/` totals about 2.2 MB. **Fix:** load only used weights, convert to WOFF2 where possible, preload at most the critical face, keep a system fallback.
- **[Performance / SEO]** `src/pages/index.astro:49` and `src/pages/recipes/index.astro:99` defer the recipe grid, even though recipe content is already available. `RecipesList` also makes a database query that can hide cards if Neon is unavailable. **Fix:** render recipe cards in initial HTML and let rating metadata degrade gracefully.
- **[Correctness]** `src/components/astro/recipe-cards/RecipeCard.astro:30` dereferences a missing image before fallback; `src/services/rates.ts:29` starts from views, so unrated/unviewed recipes have no rating row. **Fix:** safe image lookup and default statistics for every recipe.
- **[Security / integrity]** `src/pages/api/recipe/rate.ts:11`, `src/pages/api/comments/create.ts:12`, `src/pages/api/comments/index.ts:11`, `src/pages/api/user.ts:9` and avatar endpoint trust unvalidated JSON/query data. Pagination can be unbounded and profile data is directly passed to persistence. **Fix:** validate at route entry with constrained schemas and clamp pagination.
- **[SEO]** `src/components/astro/pages-structure/BaseHead.astro:5` uses the request pathname for canonical but raw request URL for social metadata; no recipe structured data, recipe index metadata, or exclusion of private profile from robots. **Fix:** canonical metadata from configured site, Recipe JSON-LD from verified content, robots noindex for private page, meaningful listing metadata.
- **[Accessibility / UX]** `src/layouts/BaseLayout.astro:24` lacks a skip link and main ID; `src/components/astro/pages-structure/Navigation.astro:31` mobile menu lacks an accessible relationship and Escape handling. **Fix:** add skip target, visible focus, menu state and Escape behavior.
- **[Correctness / crawlability]** `src/middleware.ts:73` redirects every non-API 404 to home. **Impact:** soft 404s and an unreachable 404 page. **Fix:** preserve actual 404 response and page.
- **[Architecture / build reliability]** `integrations/syncRecipesToDb.ts:18` issued one database query per recipe and wrote missing rows on every production build. **Impact:** releases depend on database access and mutate production data. **Fix:** remove the build hook; create view rows atomically on first request.

### Medium priority (9 found)

- **[Correctness / KISS]** `src/pages/recipes/index.astro:16` accepts `NaN`, negative and out-of-range page values; zero results say `Showing 1-0`. Sorting/filtering is inline with the route. **Fix:** extract pure query logic with a small interface and clamp pages.
- **[Performance]** `src/pages/recipes/[slug].astro:21` and `RecipeCard.astro:29` glob every preview image in each render. **Fix:** share one image resolver module and use responsive widths.
- **[Performance]** `src/components/astro/recipe-page/CookingStep.astro:37` upscaled 512–640px images to 1000px, increasing many files' transfer size. **Fix:** generate appropriately sized responsive variants.
- **[Accessibility]** `src/components/react/forms/SubscribeForm.tsx:45`, `src/components/react/comments/CommentInput.tsx:44` lack visible labels; `src/components/react/auth/PublicAuth.tsx:17` uses an icon-only button without an accessible action name. **Fix:** labels and explicit button names.
- **[UX]** `src/components/astro/filter/FilterSection.astro:27` has no `aria-controls` and does not mark selected filters; localStorage reads can throw. **Fix:** robust native disclosure or labeled controls, selected state, focus styling.
- **[Design]** `src/styles/global.css:15` uses bright tokens with low-contrast foreground pairings; many controls use `transition-all`. **Fix:** coherent warm palette with measured contrast, explicit transitions, reduced-motion support, 44px targets.
- **[Navigation]** `src/components/astro/pages-structure/Pagination.astro:19` has small targets and ambiguous arrow labels. **Fix:** descriptive accessible names and adequate hit areas.
- **[Dependency maintenance]** `package.json` uses npm lockfile, old Astro 5 and many loosely maintained direct dependencies; `@astrojs/node` is unused. **Fix:** migrate to pnpm, clean direct dependencies, upgrade compatible versions, then consider Astro major upgrade after adapter/auth compatibility review.
- **[Documentation]** `README.md` claims active subscription/contact and edge optimization while the routes do not implement them. **Fix:** document actual capabilities and setup, avoid unverified claims.

### Low priority (3 found)

- **[SEO / copy]** `src/pages/contact-us.astro:6` repeats the brand in its title and contains placeholder contact details/social links. **Fix:** remove fabricated details and use verified contact links.
- **[Content]** `src/pages/about.astro:141` has a `href="#"` link. **Fix:** point it to a real destination or remove it.
- **[Code quality]** `src/components/react/buttons/CustomButton.tsx:1` adds a shallow wrapper around the UI button for a single static navigation action. **Fix:** use a native anchor in static Astro content.

## Implementation and verification

- **Architecture and data:** The home and recipe listing render collection entries in initial HTML. `src/lib/recipe-query.ts` owns pure filtering, sorting, page clamping, and result ranges; `src/lib/recipe-images.ts` resolves local images with fallbacks; `src/lib/api-input.ts` centralizes request schemas and JSON responses. The recipe view count now uses one atomic upsert on first request, and the build-time database synchronization hook is gone. Recipe mutation routes reject slugs that have no content entry. These are small cohesive modules; adding classes would introduce state and inheritance without a domain need.
- **Trust and security:** Contact and newsletter copy no longer promise delivery or subscription. The former endpoints return HTTP 501 without logging user data. ImageKit signing is on demand and protected by the same private-route middleware as account APIs. Profile, avatar, comment, rating, like, and view inputs are constrained; comment pagination is bounded. A real email/newsletter provider would be a separate feature requiring provider credentials and consent design.
- **SEO and accessibility:** Canonical, social, robots, and Recipe JSON-LD metadata use the configured site and actual recipe content. Filtered listings and the private profile are `noindex`; missing paths return HTTP 404. The page has a skip link; menus expose state and close with Escape; icon buttons and form fields have names; pagination targets and filters have clearer controls.
- **Performance and UI:** Removed 14 unused TTF files (about 2.2 MB) and their global preloads. Recipe cards, detail heroes, cooking steps, and the header logo use responsive optimized assets with stable dimensions. The mobile filter panel starts compact. The palette, contrast, visible focus, touch targets, reduced motion, and honest footer/contact copy were updated. The generated `dist/client` is about 17 MB across all routes and 374 optimized image variants; that is deployment output, not a per-page transfer size.
- **Tooling:** Migrated to `pnpm@11.11.0` with a generated lockfile and approved native build scripts. Updated compatible dependency versions, removed unused direct packages, and documented Node 22+, setup, and real features. Astro remains on 5.18.2: a move to Astro 6/7 needs an adapter/Auth.js migration and regression review, not only a version bump.
